### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `skill://poteto-mode/scripts/worktree-audit.sh` (principle-build-the-lever). It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.omp/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar.
4. Pause on any content that could be lost. For tracked uncommitted changes, untracked files, and ignored files, show the exact paths and the size of every path, then get explicit user confirmation for those exact paths before removal. The audit's `wip:N` and `scratch:N` counts are signals to inspect, never permission to delete. A worktree may auto-proceed only when it is truly clean, merged, has no open PR, and is not in use; every other state pauses for a decision.
5. Prune only the confirmed set, one path at a time. A detached linked worktree has a separate safety gate: it is never removed merely because its general review row was confirmed. Before any detached removal, resolve its HEAD commit and verify that HEAD is reachable from a durable branch or tag ref, for example with `git for-each-ref --contains "$head" --format='%(refname)' refs/heads refs/tags`. If no durable ref contains HEAD, offer to create the specifically named backup ref `refs/heads/pstack-cleanup-backup/<short-HEAD>` at that exact commit, show the user its full ref name and SHA, and verify the created ref resolves to HEAD. Require explicit user confirmation before removal, and never remove an unreachable detached HEAD unless that named backup ref exists and the confirmation covers the exact worktree path and HEAD SHA. For branch-attached worktrees only, branch refs survive worktree removal, so their referenced commits remain retained. Immediately before every removal, verify that its audited state has not changed, then use the ordinary removal command `git worktree remove -- "$path"`; the path is quoted and `--` ends option parsing. If Git refuses the removal or any state changed, stop: rerun the audit and a fresh status, and show the worktree's current contents with their exact paths and sizes. Do not fall back to a stronger deletion command. If force is ever considered as a separate exceptional action, first collect a separate fresh status, then require explicit destructive confirmation naming the exact paths that would be lost; it is never automatic. After successful ordinary removals, run `git worktree prune`, then confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, plus package caches (pnpm, uv, brew, yarn). Clear only cache or generated data the user has not said to keep. Never inspect or remove editor or application state: it can contain history, recovery data, and active workspace metadata rather than cache files.

This playbook deletes only the confirmed worktrees, simulators, build products, and package caches covered by the gates above. User application state is outside its scope.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
