### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `skill://poteto-mode/scripts/worktree-audit.sh` (`skill://principle-build-the-lever`). It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.omp/worktrees/myrepo/x` (`skill://principle-encode-lessons-in-structure`). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest OMP session that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. User-designated sessions to keep and active sessions are the real artifact (`skill://principle-prove-it-works`). Get that set from the user and OMP's `/resume` list and cross-check every candidate. The audit can mark `safe` a worktree belonging to a session the user wants kept, so the session set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the session transcripts and report whether a session is active or designated to keep and which worktrees it touches (`skill://principle-guard-the-context-window`). An active session can spawn arena and repro trees into sibling worktrees through background subagents, and those are in use even when their names never appear in `/resume`.
4. Pause on any content that could be lost. For tracked uncommitted changes, show the diff. For tracked, untracked, and ignored files, show exact paths and the size of every path, then get explicit user confirmation for those paths before removal. The audit's `wip:N` and `scratch:N` counts are signals to inspect, never permission to delete. A worktree may auto-proceed only when it is truly clean, merged, has no open PR, and is not in use. Every other state pauses for a decision.
5. Prune only the confirmed set, one path at a time. A detached linked worktree has a separate safety gate. It is never removed merely because its general review row was confirmed. Before any detached removal, resolve its HEAD commit and verify that HEAD is reachable from a durable branch or tag ref, for example with `git for-each-ref --contains "$head" --format='%(refname)' refs/heads refs/tags`. If no durable ref contains HEAD, offer to create the specifically named backup ref `refs/heads/pstack-cleanup-backup/<short-HEAD>` at that exact commit. Show the user its full ref name and SHA, then verify the created ref resolves to HEAD. Require explicit user confirmation before removal. Never remove an unreachable detached HEAD unless that named backup ref exists and confirmation covers the exact worktree path and HEAD SHA. For branch-attached worktrees only, branch refs survive worktree removal, so their referenced commits remain retained. Immediately before every removal, verify that its audited state has not changed, then use `git worktree remove -- "$path"`. The quoted path and `--` prevent option parsing. If Git refuses removal or any state changed, stop, rerun the audit and a fresh status, and show current contents with exact paths and sizes. Do not fall back to a stronger deletion command. If force is considered as a separate exceptional action, collect a separate fresh status and require explicit destructive confirmation naming the exact paths that would be lost. It is never automatic. After successful ordinary removals, run `git worktree prune`, then confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, plus package caches (pnpm, uv, brew, yarn). Clear only cache or generated data the user has not said to keep, after confirming the exact simulator IDs or paths and scope immediately before deletion. Never inspect or remove editor or application state. It can contain history, recovery data, and active workspace metadata rather than cache files.

This playbook deletes only the confirmed worktrees, simulators, build products, and package caches covered by the gates above. User application state is outside its scope.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
